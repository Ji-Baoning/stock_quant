# 上下文与规则治理设计

## 目标

为 Stock Quant 建立可按任务和路径加载的文档与指令体系，使编码代理在修改约
69,000 行代码的系统时能读取权威、最小且相关的上下文；同时保留历史设计、
实施计划和运维记录的可追溯性。

## 非目标

- 不修改 Python 运行时代码、配置、数据或测试行为。
- 不删除或批量改写现有 `README.md`、`RUNBOOK.md`、`PROJECT_MEMORY.md` 与
  `docs/superpowers/` 历史资料。
- 不引入外部规则引擎或要求 CI 依赖网络服务。

## 现状与问题

仓库已经按 `data_sources`、`data_model`、`data_quality`、`research`、
`backtest`、`portfolio` 和 `reporting` 划分代码，但没有项目级 `AGENTS.md` 或
`CLAUDE.md`。当前事实分散在 README、RUNBOOK、PROJECT_MEMORY 及
`docs/superpowers/{specs,plans}`；后两者包含历史设计和实施细节，最大单文件超过
4,000 行，不能作为代理默认上下文。

## 目标结构

```text
AGENTS.md                         协议层：加载规则、优先级、最小通用约束
docs/architecture/                当前架构事实与不可违反的约束
docs/adr/                         已采纳决策及其取舍
docs/features/<feature>/          功能规格和设计边界（后续新功能使用）
docs/operations/                  运维、验收与事件记录
docs/history/{specs,plans}/       历史设计与实施记录（迁移分阶段完成）
.claude/rules/                    Claude Code 的路径作用域规则镜像
```

第一阶段只创建入口、架构事实、ADR 索引和路径规则；既有
`docs/superpowers/{specs,plans}` 继续保留原路径，直到其引用被逐项迁移。

## 协议层

根目录 `AGENTS.md` 是 Codex 等支持层级指令的客户端入口；根目录
`CLAUDE.md` 为 Claude Code 提供同义入口。二者只描述：

- 修改前按任务加载哪些文档；
- 规则优先级；
- 当前项目不可违反的通用约束；
- 文档的权威性和更新责任。

它们不得复制详细模块知识、命令手册或历史决策。任何一份入口控制在约 120 行内。

规则优先级固定为：即时用户指令 > 安全与平台指令 > 路径作用域规则 > 根协议层 >
架构不变量 > ADR > 功能规格 > 运维记录 > 历史资料。发生同层冲突时，路径更具体的
规则优先；仍无法判定时，停止修改并在结果中说明冲突，而不是自行选择。

## 架构事实层

`docs/architecture/` 由四个小而稳定的文件组成，每份应不超过 400 行：

- `overview.md`：系统定位、核心技术和高层组件关系。
- `module-map.md`：包职责、允许依赖方向和修改前应阅读的边界。
- `data-flow.md`：数据采集到发布、验收到研究及报告的关键生命周期。
- `invariants.md`：不可绕过的数据集、验收、点时股票池、研究冻结和发布约束。

内容只陈述当前已由代码、测试或已确认文档支持的事实；不把尚未执行的计划表述为
已实现能力。每一条强约束尽可能指向现有测试、代码模块或权威运维文档。

## 决策记录层

`docs/adr/` 使用简洁 MADR 风格和 YAML frontmatter。`DECISIONS_INDEX.md` 按主题
列出 ADR、状态、受影响路径和关键词，供代理先检索再按需读取。

第一阶段将高影响且稳定的决定提炼为 ADR：内容寻址与不可变发布、真实数据验收、
点时指数成分、Walk-forward OOS、以及路径显式项目根。ADR 解释“为何”和“拒绝了
什么”，不重复实现细节。

## 路径规则与按需加载

`.claude/rules/` 用主题文件描述受影响路径及其必须加载的架构文档。根协议层为所有
代理给出等价的加载表，以便未解析 Claude 规则的客户端仍有一致行为。

规则覆盖：数据源、数据模型与质量、研究与回测、组合构建、配置与项目脚本、测试。
一个规则文件只包含该范围的边界、不变量、必须读取的资料和验证要求；不复制其他
领域规则。

## 文档生命周期

- 架构事实：随当前代码演进更新，过时内容应在同一变更中修正。
- ADR：一经采纳不可原地改写结论；新决定以 supersede ADR 表示。
- 功能规格：功能实现前创建，完成后保留验收标准。
- 运维记录：按日期追加，描述事实和证据。
- 历史设计与计划：仅作追溯，不作为新实现的默认事实来源。

README 保持面向使用者的简短项目说明；RUNBOOK 保持操作步骤；PROJECT_MEMORY 保持
长期业务背景。它们可链接到架构文档，但不得再次成为架构契约的唯一来源。

## 轻量校验

第一阶段加入一个无第三方依赖的检查脚本，并由 pytest 调用。它验证：

- 根入口、四份架构文档、ADR 索引和各路径规则存在；
- 文档行数不超过 400 行，入口不超过 120 行；
- ADR 索引中的每一个链接都指向存在的 ADR；
- 路径规则包含路径作用域和至少一个按需加载引用；
- 入口明确写出优先级与冲突处理。

检查只约束新增治理层，不对现有历史长文档设行数限制。

## 验收标准

1. 从根入口可找到每类权威文档及加载时机。
2. 代理修改任一核心模块时，能由路径规则定位相关不变量和 ADR。
3. 历史计划不再被定义为当前事实的默认来源。
4. 文档结构校验在默认 pytest 运行中通过。
5. 不修改现有运行时代码、数据、配置或用户未提交的工作。
