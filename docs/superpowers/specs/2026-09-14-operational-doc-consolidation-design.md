# 运行文档与脚本治理收敛设计

## 目标

将根目录 `RUNBOOK.md` 确立为唯一的操作手册，删除 `project/RUNBOOK.md`，并减少
长期记忆、一次性脚本与可再生资产造成的入口歧义；不删除不可变数据、验收记录或
历史设计资料。

## 范围与非目标

- 根 `RUNBOOK.md` 是仓库与运行时项目的唯一命令流程来源；其命令使用显式
  `--root project` 或等价的项目根说明。
- `project/RUNBOOK.md` 在根文档完成内容补齐后删除，不保留副本、软链接或重定向。
- 不删除 `project/data/standardized/` 的历史版本、原始证据、验收清单或实验工件。
- 不移动、删除或改写 `docs/superpowers/{specs,plans}` 的历史材料。
- 不改变 CLI、数据发布、研究或配置的运行时行为。

## 文档职责

| 文档 | 唯一职责 | 不再承担 |
| --- | --- | --- |
| `RUNBOOK.md` | 可执行的运行、验收、诊断流程 | 长期业务背景、架构决策全文 |
| `README.md` | 项目定位、安装与导航 | 完整操作步骤 |
| `PROJECT_MEMORY.md` | 业务背景、时间线、未决事项 | 当前架构事实和命令副本 |
| `docs/architecture/` | 当前实现事实与约束 | 日期化运行记录 |
| `docs/adr/` | 决策理由与被拒绝替代方案 | 实施步骤 |
| `docs/operations/` | 日期化证据与事故/验收记录 | 默认命令入口 |

删除前逐节比较两个 RUNBOOK：根文档缺少但仍适用的项目根、传输环境、验收或诊断
细节必须移入相应根章节；过期内容不迁移。根文档新增内容必须使用明确项目根，不能
假定调用者已 `cd project`。

## 长期记忆收敛

`PROJECT_MEMORY.md` 保留项目定位、目标权衡、时间线、已知限制和未决事项。每一段
当前代码结构、数据流、不变量或已采纳决策，改写为一两句状态摘要加至
`docs/architecture/` 或 `docs/adr/DECISIONS_INDEX.md` 的链接；不重复门禁规则、
指标公式或操作命令。历史事实仍可保留，但必须标明日期和“历史记录”身份。

## 脚本清单

新增 `project/SCRIPTS.md`，按以下状态列出顶层 Python 脚本及其唯一定位：

- `active`：当前运维或证据链仍需使用的辅助脚本；必须列出正式 CLI 替代项（若有）。
- `diagnostic`：只读检查、探针或解释性报告；不得作为发布路径。
- `migration`：一次性重建、回补、导入或转换；明确输入、输出与不可重复的前置条件。
- `retired`：仅为复现历史保留；不得用于新发布。

清单不移动脚本。每个脚本的模块首段增加简短状态标记；没有正式 CLI 替代项的
脚本必须明确其保留理由。正式发布始终以 `python -m stock_quant ...` 为准。

## 资产保留规则

新增 `docs/operations/asset-retention.md`，区分：

- 不可删除：内容寻址数据集、原始证据、验收记录、实验与挑战工件；它们是可复现性
  和审计的一部分，即使其中表字节相同。
- 可再生且不应提交：`.venv/`、`.pytest_cache/`、`.ruff_cache/`、`.codegraph/` 与
  `.superpowers/` 工作区。
- 人工确认后才可删除：`phase-one-*.bundle` 等离线恢复包；确认不再承担恢复或交付
  职责后，才从版本库移除。

## 验收

1. 仅根 `RUNBOOK.md` 存在并被 README、AGENTS/CLAUDE 的操作路径引用。
2. 根 RUNBOOK 覆盖已删除项目 RUNBOOK 的所有仍适用流程，且不要求隐式工作目录。
3. `PROJECT_MEMORY.md` 不再复制当前架构不变量或完整命令流程，而是链接到权威层。
4. `project/SCRIPTS.md` 覆盖每个顶层 Python 脚本并说明状态与用途。
5. 资产规则明确禁止删除不可变发布数据；只读检查验证文档链接与脚本清单完整性。
6. 不覆盖当前未提交的根 RUNBOOK 或其他用户工作。
